Две ревизии: первая — на середине работы, по составу тем; вторая — после завершения, по фактическому состоянию текста. Обе проводились измерением, а не чтением по диагонали.

# Ревизия №2 · документ завершён

**Дата:** 2026-09-02 · **предмет:** 151 карточка, 22 файла, ~79 000 слов.

## Метод

Три скрипта над исходниками: разбор карточек на секции, построение графа внутренних ссылок, сверка с реестром и с плейлистом. Проверялось: распределение объёма, наличие обязательных разделов, число источников, входящие и исходящие связи, покрытие видео, повторное объяснение одних и тех же механик, покрытие карточек справочниками.

Две метрики пришлось переделать: первая версия проверки «есть ли альтернативы» искала заголовок и не видела таблиц сравнения с другими названиями колонок, а проверка использования видео смотрела только карточки и не учитывала workflow. Обе давали ложные находки — цифры ниже получены после исправления.

## Что проверено и оказалось в порядке

Отрицательные результаты важны не меньше находок:

- **Целостность ссылок.** 0 битых якорей, 0 ID вне диапазона блока, 0 подписей, не совпадающих с целью, 0 дубликатов ID, порядок ID монотонный во всех 12 файлах.
- **Видео.** Все **103 из 103** упомянуты в документе — 84 в карточках, остальные в workflow и в карте плейлиста. Ни одно не потеряно.
- **Дублирования механик нет.** Проверялись самые «сквозные» темы: идемпотентность упоминается в 6 карточках, но механизм (ключ, уникальный индекс, хранение результата) объясняется **только** в T-016 — остальные ссылаются. То же для outbox, кворумов, саги, backpressure. Опасение, что одно и то же будет объяснено трижды, не подтвердилось.
- **Источники.** Медиана 4 внешние ссылки на карточку, 369 уникальных источников. Все 137 полноразмерных карточек имеют разделы «Источники» и «Связано».
- **Распределение объёма.** Медиана по блокам 323–439 слов на карточку — ровно, без выбросов на уровне блоков.

## Находки

### P1 · Workflow почти не связан с карточками — ✅ исправлено (итерация D)

**Данные:** из карточек на шаги workflow ведут **157** ссылок, обратно — **5**. В `00-workflow.md` одиннадцать строк «Связано», но пути в них записаны моноширинным текстом (`` `topics/03-storage-and-data.md#sharding` ``), а не ссылками — то есть некликабельны. Ещё они указывают на файл целиком, а не на карточку. У шага W11 связей нет вовсе.

**Почему это главная находка.** Трёхслойная структура обещала: «из шага workflow — ссылки на карточки, из карточки — обратно на шаг». Обратное направление работает, прямое — нет. Ломается основной сценарий: идёшь по процессу проектирования, упираешься в «выбрать ключ шардирования» и не можешь провалиться в тему.

**Что сделано (итерация D).** Все 14 путей в моноширинном тексте заменены адресными ссылками; каждый из 12 шагов получил 5–8 ссылок на конкретные карточки плюс, где уместно, ссылку на блок целиком; шаг W11 связан с обзором отказоустойчивости, сверкой данных, моделью угроз, SLO и обоими справочниками. **Было 5 ссылок workflow → карточки, стало 82**; из workflow напрямую достижимы 72 карточки из 151. Побочный эффект: карточка T-076 «Карта паттернов» перестала быть недостижимой.

### P1 · Девять коротких кейсов без источников

**Данные:** T-142…T-150 — единственные карточки в документе с **нулём** внешних ссылок и без раздела «Источники».

**Почему.** Требование «для всего приводи источники» выполнено везде, кроме этих девяти. При том что кейсы — самая прикладная часть, и читателю там особенно нужно, куда идти дальше.

**Что делать.** Добавить по 2–3 источника в каждый: инженерные разборы и первоисточники по теме (например, для rate limiter — статья Stripe, для уведомлений — документация провайдеров доставки, для геопоиска — H3 и PostGIS).

### P2 · Карточки-решения без сопоставления вариантов

**Данные:** таблицу сравнения или блок «когда что» имеют 74 из 151 карточки. Среди остальных большинство — описательные (как работает интернет, коды состояния, типовые атаки), где выбора нет и таблица была бы искусственной. Но **16 карточек описывают именно выбор** и сопоставления не содержат:

T-053 патологии кэша · T-060 гарантии доставки · T-062 ретраи и DLQ · T-078 границы сервисов · T-085 serverless · T-086 mesh, sidecar, BFF · T-100 сессии против токенов · T-107 шифрование · T-115 контейнеры · T-116 Kubernetes · T-118 observability · T-122 ёмкость · T-123 тестирование · T-131 конкурентность · T-133 пулы и N+1 · T-138 стоимость.

**Что делать.** Добавить в каждую компактную таблицу «вариант — когда лучше — чем платим». В T-100 и T-115 сравнение и есть содержание карточки, оно просто изложено прозой.

### P2 · Десять карточек, на которые никто не ссылается

**Данные:** T-002 (OSI), T-020 (API vs SDK), T-076 (паттерны распределённых систем), T-125–T-127 (справки о ролях, монорепо, релизе мобильных), T-139, T-140, T-150, T-151 (кейсы).

Кейсы — листья по построению, на них и не должны ссылаться. **T-076 «Карта паттернов»** закрыта итерацией D — на неё теперь ведёт шаг W4. Осталось восемь: T-002 и T-020 стоит связать (на модель OSI естественно ссылаться из карточки балансировки, на API vs SDK — из версионирования и контрактов), T-125–T-127 — из вводной части блока B10, а четыре кейса остаются листьями по построению.

Оговорка по методу: «сирота» здесь означает «нет ссылок из текста карточек и из workflow». Навигационные строки в начале каждого блока ссылаются на все карточки своего блока, поэтому формально недостижимых нет ни одной — но через оглавление, а не по смысловой связи.

### P3 · Короткие кейсы тоньше остального документа

**Данные:** T-142–T-150 — 131–160 слов при медиане по документу 340–420. Это было сознательное решение («короткий разбор»), но вместе с отсутствием источников они выглядят незаконченными, а не компактными.

**Что делать.** Довести до 200–250 слов за счёт одного конкретного числа или примера в каждом — не за счёт воды.

### P3 · Отсутствующие разделы в шести полноразмерных карточках

Без «Trade-offs»: T-001, T-008 (gRPC), T-021, T-106, T-129, T-131. Без «Что мерить»: T-002, T-008, T-020, T-021, T-128. Для обзорных (T-076, T-151) и кейсов это нормально, для перечисленных — упущение: у gRPC есть заметные компромиссы (балансировка долгоживущих соединений, бинарная отладка), они упомянуты в тексте, но не выделены.

### P3 · Справочники покрывают документ неравномерно

`90-cheatsheets.md` ссылается на 20 карточек, `91-antipatterns.md` — на 55, `92-glossary.md` — на 66. Ни в одном не упомянуты 47 карточек. Для глоссария это нормально (не каждая тема — термин), для шпаргалки — недоработка: числа и матрицы стоит связать плотнее.

# Ревизия №1 · на середине работы

**Дата:** 2026-09-02, при 65 написанных карточках. Предмет — состав тем, а не текст.

Нашла три вида перекоса, унаследованного от плейлиста: **инструменты вместо свойств** (13 видео про Docker, Kubernetes и Git при нуле про наблюдаемость и ёмкость), **транспорт вместо данных на транспорте** (версии HTTP разобраны, кэширование и форматы отсутствуют), **реляционное вместо остального** (ни time-series, ни графовых, ни векторных, ни геоданных).

**Итог:** добавлено 24 темы — 12 в написанные блоки (закрыты итерациями A, B, C) и 12 в тогда ещё не написанные. Отдельно принято решение оставить короткими справками пять тем (роли DevOps/SRE, монорепо, релиз мобильных, Big-O, сборка мусора), чтобы инструментальный перекос не воспроизвёлся объёмом текста. Решение выполнено: эти карточки — 115–164 слова.

Решено **не** расширять блок кэширования и не заводить отдельные карточки под Memcached и векторные часы — отрицательные решения тоже часть ревизии.
